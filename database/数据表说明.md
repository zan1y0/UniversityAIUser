# 本地数据模型

app_users：账号、展示名、BCrypt 密码哈希。idempotency_records：24小时操作键、规范化请求指纹和原响应。event_outbox：按用户保存 SSE 与通知事件。

profiles、avatar_preferences、reminder_preferences、checkins 对应个人档案与督学；programs、knowledge_trees、subjects、books、questions、papers 对应公共课程资料和题库；evaluations、conversations、qa_messages、recognitions、practice_sessions、attempts、wrong_items、plans、exam_sessions、exam_submissions、exam_results、score_snapshots、interviews、interview_turns、interview_reports、study_events、news_follows、notifications 对应个人业务；notices、notice_revisions、milestones 对应公共政策；jobs、job_commands、files 对应技术支持。

聚合表统一包含 id、owner_id、version、payload、created_at、updated_at，独立表与索引区分业务，payload 采用契约 JSON 文本快照；公共聚合 owner_id=public，个人聚合为登录用户 UUID。文件内容保存在受鉴权保护的私有目录，表中仅保存元信息。正确答案保存在 questions 的服务端内部快照中，展示 DTO 仅取 question，提交后才返回评分结果。

计划任务和模考答案作为所属聚合的子项在事务中更新，使用聚合版本 CAS。userId 从 SESSION 取得；请求里的 owner_id / userId 会被契约拒绝。每个 userId 的写请求先获取 app_users 行锁，再在同一事务写业务和幂等记录。本地规模下该设计便于可靠验证；有独立索引/分页查询需求时应迁移子项为关系表，而不是在代码里无约束扩展 JSON。

Flyway 两份 V1 为相同表结构，MySQL 脚本已保存但没有在本机 MySQL 执行。H2 的验证不能证明 MySQL 驱动、用户权限、字符集与真实并发事务表现。
