# 模型训练后端接入说明

日期：2026-11-20。范围：UniversityAIUser Java 后端，不包含模型训练、权重或 Python 服务。

## 已落地的接入

- `HttpMasteryPredictor` 改用 `POST /v1/mastery`，发送 `userId/subjectId/mode/history/candidates/topK`。按接口契约选择 `mode=practice`，不采用执行手册中冲突的策略枚举。
- 历史取按时间排序的最近 100 条有效练习及已评分模考记录。`correct` 转为 0/1，缺失耗时填 0、尝试次数填 1。旧接口只用其日期范围内的练习流，保留原统计分母。
- `candidates` 按契约示例传本学科候选知识点 ID 字符串；历史中的题目版本映射为业务题目 ID，已下线且不能映射的历史题保留版本 ID。
- 默认连接/读取超时分别 800ms，不重试；4xx 记警告以排查参数，5xx、断连、超时、无效 JSON 或版本不符均降级。
- 解析 `knowledgeMastery`，保留标准差、融合权重和来源；不自行编造置信度。未作答知识点返回 `mastery=null`；非法掌握度回退到该知识点的真实正确率。
- 解析 `recommendedQuestions`，按 rank 排序、去重，并校验题目属于当前学科。业务题目 ID 无法唯一定位版本时跳过该推荐，不随意选一个版本。
- 推荐保留 `questionId/rank/ucbScore/confidence`，同时保留已有 `questionVersionId` 供练习入口使用。中文 `reason` 适配为已有的 `reason.message`，避免破坏前端。未知/越界的推荐不直接透传。
- `op049`、`op073` 接入模型估计；`KnowledgeProgress.items` 四字段和 `additionalProperties:false` 不变。`op139`、`op140` 增加可选顶层 `algorithmVersion`。
- 60 秒、最多 512 项缓存，按用户、科目、模型版本及完整输入的 SHA-256 隔离。作答、评分、题库和先修关系变化后不复用旧结果。
- H2/MySQL 新增 Flyway V15，建立 `kt_prediction_results`；每次相关接口返回均记录用户、科目、操作、实际算法版本、耗时、缓存命中和完整业务响应。`result_json` 是 API envelope 内的 `data`，不包含答案或解析。
- `contracts/openapi.json` 为唯一修改源，其他契约和前端类型由原有同步脚本生成；新增 `KnowledgeMasteryDetail`，复用已有扩展结构。

## 降级的实际边界

运行时可用路径为：模型成功 → 使用有效结果；模型有掌握度但没有可用推荐 → 按掌握度升序做贪心推荐（`kt-greedy-v1`）；模型完全不可用 → 规则正确率（`empirical-correct-rate-v1`）。规则推荐优先复习已观察到的薄弱知识点，再用稳定排序处理冷启动题目。

没有把原来的普通 UCB 排序改名为 LinUCB，也没有伪造 `kt-bandit-v1`。完整的 `model → bandit → greedy → rule` 中，bandit 当前作为不可用策略跳过：

1. HTTP 契约定义 `mode=practice/exam/review`，执行手册却定义 `mode=model/bandit/greedy`，且未提供单独 bandit 推理地址。不能向服务擅自发送未确认的策略参数。
2. 仓库没有 LinUCB 权重、在线状态或 Python 源码，Java 不能在模型服务关闭时凭空恢复其策略状态。
3. `/v1/bandit/feedback` 虽有请求示例，但没有推荐曝光 ID、真实作答的关联约定和 reward 计算口径。自动把“答对”当作学习收益会引入错误训练信号，因此本次不自动上报，也不新增一个允许前端任意填写奖励的接口。

训练侧确认策略调用协议、反馈关联和 reward 定义后，才能接通这一层并验证四级策略。当前模型服务关闭时，接口会如实返回规则版本和来源。

## 配置和联调

默认 `AI_KT_ENABLED=false`，不会访问 Python。由训练侧在后端所在机器启动 Python 服务后，在启动 Java 的同一 PowerShell 中设置：

```powershell
$env:AI_KT_ENABLED = 'true'
$env:AI_KT_BASE_URL = 'http://127.0.0.1:8000'
$env:AI_KT_MODEL_VERSION = 'kt-gkt-v1'
$env:AI_KT_TIMEOUT_MS = '800'
```

然后按项目原有方式启动后端。Python 若在另一台机器上，地址必须改为那台机器可访问的地址；`127.0.0.1` 只代表后端自己所在机器。模型版本须与 Python 返回值一致；回滚通过修改模型服务部署版本及环境变量完成，Java 不负责热加载权重。

登录学生账号后调用：

- `GET /api/v1/analytics/mastery-estimates?subjectId=<真实科目 UUID>`
- `GET /api/v1/analytics/recommendations?subjectId=<真实科目 UUID>`
- `GET /api/v1/practice/knowledge-progress?subjectId=<真实科目 UUID>&timeRange=all`
- `GET /api/v1/analytics/training-sequence?subjectId=<真实科目 UUID>`

候选知识点 ID 和模型返回的业务题目 ID 必须与项目实际目录一致。训练侧尚未提供这种 ID 映射的运行产物，因此真实模型能否返回本项目题目还需联调，不能用公开数据集题号冒充本项目 UUID。

查询本次实际版本分布（请求口径；缓存命中也计数）：

```sql
SELECT operation_id, algorithm_version, cache_hit, COUNT(*) AS request_count
FROM kt_prediction_results
GROUP BY operation_id, algorithm_version, cache_hit;
```

不同接口的版本可能不同：例如掌握度由模型估计、推荐由本地贪心产生。部分知识点回退规则时，顶层标记包含的模型版本，各条目的 `source/modelVersion` 说明实际来源，不应仅凭顶层版本宣称全部知识点均由模型推理。

## 尚需外部交付或确认

- 真实 DKT/SAKT/AKT/GKT、DANN、MC-Dropout、校准、LinUCB 的训练和权重，以及数据清洗、AUC/ECE 等实验指标：由训练侧交付，不在 Java 中重写或伪造。
- Python `/health`、`/v1/model/info`、`/v1/reload`：由训练侧实现，Java 不对前端暴露权重重载接口。
- LinUCB 独立降级及反馈闭环：需要上面所列协议和奖励口径。
- 真正的先修关系、知识点概念/计算/记忆分类等人工标注：现有后端支持的字段和知识树不能替代学科标注，不能把父子层级直接当作已确认的先修关系。
- 旧记录缺失的真实耗时、改答等信息不能追溯恢复；新字段仍依赖调用方实际上传，缺失时保持空值，模型请求按契约补默认值。
- 真实模型精度、模型服务 p95 和 MySQL 实例运行情况需要对应外部环境验证；本地 HTTP 测试替身通过不代表真实模型联调完成。
