## 1. 服务端 HTTP 契约（后端作为调用方）

训练侧在本地启动的 Python 服务，后端通过 HTTP 调用。**以下字段一经确认不得单方面变更**，需变更时先改本文 + `openapi.json` 再各自改代码。

### 1.1 `GET /health`

存活探针。

```json
{"status": "ok", "modelLoaded": true, "modelVersion": "kt-gkt-v1"}
```

### 1.2 `GET /v1/model/info`

模型元信息，用于日志与问题定位。

```json
{
  "modelVersion": "kt-gkt-v1",
  "track": "b",
  "trainedAt": "2026-11-18",
  "nItems": 719,
  "metrics": {"auc": 0.9104, "acc": 0.8378}
}
```

### 1.3 `POST /v1/mastery`（主接口）

入参：

```json
{
  "userId": "u_1001",
  "subjectId": "math",
  "mode": "practice",
  "history": [
    {"questionId": "q_1", "knowledgeId": "k_3", "correct": 1, "durationMs": 12000, "attemptNo": 1, "answeredAt": "2026-11-17T10:00:00"}
  ],
  "candidates": ["k_3", "k_7", "k_12"],
  "topK": 5
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `userId` | string | 是 | 学生唯一标识 |
| `subjectId` | string | 是 | 科目，用于多科目隔离 |
| `mode` | string | 是 | `practice` / `exam` / `review`，决定推荐策略 |
| `history` | array | 是 | 按时间升序的作答记录，服务端只取最近 100 步 |
| `history[].knowledgeId` | string | 是 | 知识点 id，缺失知识点归入 `__unknown__` |
| `history[].correct` | int | 是 | `1` 答对 / `0` 答错 |
| `history[].durationMs` | int | 否 | 作答耗时，缺失填 `0`（不影响调用成功） |
| `history[].attemptNo` | int | 否 | 该题第几次尝试，缺失填 `1` |
| `history[].answeredAt` | string | 否 | ISO8601，缺失时服务端按步序推断 |
| `candidates` | array | 否 | 候选题/知识点集合，为空则返回掌握度不返回推荐 |
| `topK` | int | 否 | 推荐条数，默认 5，上限 20 |

出参：

```json
{
  "modelVersion": "kt-gkt-v1",
  "knowledgeMastery": [
    {"knowledgeId": "k_3", "mastery": 0.72, "sampleCount": 8, "stddev": 0.11, "weight": 0.8, "source": "model"}
  ],
  "recommendedQuestions": [
    {"questionId": "q_88", "rank": 1, "ucbScore": 0.63, "confidence": 0.74, "reason": "先修 k_2 未达标"}
  ],
  "latencyMs": 87
}
```

| 字段 | 说明 |
| --- | --- |
| `mastery` | 0–1，未作答过的知识点返回 `null`（**不要返回 0**，0 表示"确定不会"） |
| `sampleCount` | 参与计算的作答样本数 |
| `stddev` | 掌握度不确定性，供前端展示"置信度" |
| `weight` | 融合权重（模型预测与规则率的混合比例），0–1 |
| `source` | `model` / `bandit` / `rule`，标明本次结果来自哪一层，便于排查降级 |
| `confidence` | 推荐置信度 0–1 |
| `reason` | 中文短句，前端可直接展示 |

### 1.4 `POST /v1/bandit/feedback`

推荐反馈闭环，用于 LinUCB 在线更新。

```json
{"userId": "u_1001", "knowledgeId": "k_3", "recommended": 1, "reward": 0.8}
```

### 1.5 `POST /v1/reload`

热加载新权重的文件路径，**仅训练侧本地使用**，不对前端暴露。

### 1.6 状态码约定

| 码 | 场景 | 后端应如何反应 |
| --- | --- | --- |
| 200 | 正常 | 使用返回结果 |
| 400 | 入参不合法（如 `correct` 非 0/1） | 记为后端 bug，修调用参数 |
| 422 | 字段校验失败 | 同上 |
| 500 | 服务内部异常 | **走降级**，不重试超过 1 次 |
| 连接超时 | 服务未启动或卡死 | **走降级** |

## 2. 后端需要实现的 Java 侧

### 2.1 抽象接口

```java
public interface MasteryPredictor {
    Optional<MasteryResult> predict(MasteryRequest request);
}
```

**约定**：返回 `Optional.empty()` 表示"本次预测不可用"，**不得抛异常给上层**。上层据此降级。

### 2.2 三个实现

| 实现类 | 职责 | 关键约束 |
| --- | --- | --- |
| `HttpMasteryPredictor` | 调用 Python 服务 `POST /v1/mastery` | 连接超时 **800ms**、读超时 **800ms**；捕获所有异常返回 `Optional.empty()`；不做重试（或最多 1 次） |
| `RuleMasteryPredictor` | 现有统计口径兜底 | 复用 `AnalyticsService` 的 `empirical-correct-rate-v1`，直接返回正确率 |
| `FallbackMasteryPredictor` | 编排降级链 | 顺序：`model → bandit → greedy → rule`，逐级尝试，任一级成功即返回 |

### 2.3 降级链行为（必须按此实现）

```
调用 /v1/mastery
  ├─ 200            → 用模型结果，algorithmVersion = kt-gkt-v1
  ├─ 超时/5xx/异常   → 用 bandit 结果，algorithmVersion = kt-bandit-v1
  ├─ bandit 不可用   → 用贪心推荐，algorithmVersion = kt-greedy-v1
  └─ 全部失败        → 用规则正确率，algorithmVersion = empirical-correct-rate-v1
```

**验收要求**：Python 服务关闭时，前端请求必须仍然返回 HTTP 200 且页面正常显示，只是 `algorithmVersion` 变成 `empirical-correct-rate-v1`。

### 2.4 落库要求

每次预测结果落一张表（表名后端自定），至少包含：

| 字段 | 说明 |
| --- | --- |
| `user_id` / `subject_id` | 请求维度 |
| `algorithm_version` | 本次实际生效的版本，用于统计降级率 |
| `latency_ms` | 端到端耗时 |
| `result_json` | 完整响应体 |
| `created_at` | 时间戳 |

**用途**：可统计"模型命中率"，答辩时能给出"模型生效 92%，其余走规则兜底"这类真实数据。

## 3. 契约变更（`contracts/openapi.json`）

### 3.1 必须保持不变

`KnowledgeProgress.items` **继续保持四字段**，`additionalProperties: false` 不得放宽：

```json
{"knowledgeId": "...", "attemptCount": 0, "correctCount": 0, "mastery": 0.0}
```

- `algorithmVersion` 为 1–64 字符自由串，新增取值**不需要改 schema**
- **禁止**往 `KnowledgeProgress.items` 里加 `confidence`、`stddev` 等字段（会破坏前端现有解析）

### 3.2 必须新增

| 新增项 | 说明 |
| --- | --- |
| `GET /api/v1/analytics/recommendations` | 推荐结果接口，出参对齐本文 §1.3 `recommendedQuestions` |
| `KnowledgeMasteryDetail` schema | 承载 §1.3 `knowledgeMastery` 的扩展字段（如需要对外暴露置信度时使用） |

### 3.3 契约同步流程

```
contracts/openapi.json（唯一源）
  ├─ python scripts/sync-contract.py        生成后端副本
  ├─ python frontend/scripts/generate-contract.py  生成前端类型
  └─ --check 校验 7 份拷贝一致
```

**任何字段改动只允许改源文件，然后跑同步脚本**，禁止手改生成物。

## 4. `algorithmVersion` 取值表

| 取值 | 含义 | 触发条件 |
| --- | --- | --- |
| `kt-gkt-v1` | GKT 模型预测 | 模型服务正常 |
| `kt-dkt-v1` | DKT 模型预测 | 备用模型（主模型不可用时） |
| `kt-bandit-v1` | LinUCB 推荐 | 模型不可用但反馈数据可用 |
| `kt-greedy-v1` | 贪心兜底 | bandit 也不可用 |
| `empirical-correct-rate-v1` | 现有统计正确率 | 全部失败（现有实现，保持不变） |

前端按此值展示不同的置信度文案，**不得出现未登记的新取值**。

## 5. 数据字段依赖（见《后端数据字段待完善清单》）

训练侧当前用公开数据集，**不阻塞**后端补字段。下列字段补齐后模型精度可提升，优先级见该文档 P0 项：

| 字段 | 现状 | 影响 |
| --- | --- | --- |
| `attempts.durationMs` | 缺失 | 有真实作答时长可替换当前的"步数差"代理特征 |
| `attempts.changed` | 缺失 | 无法区分"改答"与"重做" |
| `exam_sessions.answers.correct` | 缺失 | 模考数据无法进入训练序列 |
| `attempts.attemptNo` | 缺失 | 重试次数只能推断 |
