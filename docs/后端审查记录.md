# UniversityAIUser 后端审查与验证记录

日期：2026-10-13。修改项目：`D:/STUDY/UniversityAIUser`。严格沿用课程题目 11 模块与现有 Apifox OpenAPI：81 操作、216 Schema。前端契约文件哈希与后端原始契约一致，没有修改路径或字段来迁就后端。

原脚手架可以作为 Spring Boot 基础，但业务实现和前端契约不匹配：旧 `/api/user` 等路由、数值 code、未实现登录、多处 null 返回、缺少迁移及版本幂等控制、直接返回含密码实体。旧源码已在工作区完整备份；新源码在 IDEA 项目中直接实现。

## 修改结果

- 12 个显式路由控制器覆盖 11 业务模块和技术支持；契约校验前后端请求、查询、路径、枚举、联合类型与响应。
- SESSION 登录、BCrypt、CSRF、Cookie 属性、用户归属检查、事务、乐观版本、24小时幂等响应重放。
- 刷题/错题/同类题、规则计划生成确认完成调整、模考自动保存恢复批改排名估分、复试、学习事件及统计、关注/资讯/提醒的真实业务实现。
- 模型 JSON 适配、图片识别及音频转写接口；不配置服务时明确失败，不以测试数据冒充 AI。主观题评分失败保留客观题成绩，总分保持 null。
- 私有文件下载鉴权、魔数/MIME/用途/10MiB限制、WAV时长验证；其他音频格式接入可选 ffprobe。
- 异步任务持久化、任务完成/失败事件、断线事件游标、会话失效断开、取消时丢弃后到结果、服务端到时交卷与任务提醒。
- Spring JDBC 持久化和 Flyway；local 使用 H2。MySQL 37 表脚本已保存，按用户回复尚未连接或建库；没有进行 Nginx 部署。

## 已通过的验证

`mvn verify` 通过，21 项测试，0 失败、0 错误、0 跳过。包含 276 次记录的控制器请求，以及专项二进制上传/下载、SSE、模型成功与取消竞争验证。

这些是实际 Spring 控制器、业务逻辑和 H2 事务/持久化测试。MockMvc 不建立 TCP 连接，不能等同于从 Apifox 到电脑后端的 HTTP 联调。测试专用模型替身仅验证成功分支的流程，不证明外部 AI/OCR/评分结果质量。

关键验证包括登录前/后 CSRF、错误密码、越权404、严格字段和UUID校验、版本409、并发幂等单次创建、题目无答案字段、提交后错题解析、草稿确认与进度、交卷后不能改答、成绩快照、重复学习时长去重、空样本null、实际WAV解码、服务端考试截止、模型失败时部分成绩、模型调用期间快速取消且无后到结果。
