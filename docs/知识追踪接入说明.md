# 知识追踪接入说明

对应《后端数据字段待完善清单》F1–F18，API 契约版本 1.6.0，落地日期 2026-11-17。

| 条目 | 落地内容 |
| --- | --- |
| F1、F2 | 练习记录可选的毫秒时长与改答标记，服务端写入会话序号、题内提交次数和知识点、科目快照。幂等重放复用原有记录。 |
| F3、F4 | 完成评分后回写逐题对错、分数、知识点与作答状态，模考评分维度含题目和版本标识。保存答案可携带累计逐题时长，也可显式跳过。 |
| F5 | 新增掌握度估计、带证据的推荐和本人训练序列接口。旧知识进度与薄弱雷达沿用原契约和经验正确率。 |
| F6–F9 | 知识节点支持显式先修边、分类、层级和知识点版本，题目支持标准难度与知识点版本快照。本地新建目录含样例数据；历史目录由数据维护方按实际内容补全。 |
| F10–F13 | 自训模型 HTTP 客户端默认关闭，支持配置版本、版本登记、60 秒缓存和本地推荐降级。 |
| F14–F18 | 校验提交内容与时长，导出标记历史数据质量，按登录身份限制归属并输出稳定的用户伪标识，记录推理延迟、来源、版本和降级原因，附契约及模型调用测试。 |

## 读取训练序列

- 调用 `GET /api/v1/analytics/training-sequence?page=1&pageSize=100`。可传 `subjectId`。翻页时保留首次响应的 `asOf`，避免纳入该时点之后产生的标签。此接口只读本人记录，输出不含作答内容、参考答案或解析。
- `createdAt` 是本次训练事件时间。新练习使用后端收到提交的时间，模考使用该题最后保存时间，无保存记录时使用交卷时间。旧练习使用原记录的 `createdAt`。所有时间为 UTC，旧统计接口仍按 `Asia/Shanghai` 划分本地日期。
- `scoredAt` 是标签产生时间。按过去某个时点做特征时，只消费当时已有标签的记录。`seq` 是会话内序号，练习按有效提交分配，模考对应试卷题序。导出按事件时间排序，使用会话 ID、`seq` 和事件 ID 打破同时间戳的并列。
- 筛选 `correct != null` 可得到带二值标签的有效作答。`scoreRatio` 是有效作答的得分率，主观题的二值标签使用 60% 阈值。跳过和漏答的 `correct` 为空。未完成评分和缺少可靠逐题关联的历史模考不进入导出。
- 历史练习的知识点映射优先来自练习会话快照，其次查原题目版本。无法映射、空答案或非法分数没有训练标签，质量标记在 `qualityFlags`。客户端旧版本没有采集到的时长保持为空。历史练习序号由时间和记录 ID 推导。

## 接入推理服务

`GET /api/v1/analytics/mastery-estimates?subjectId=…` 与 `GET /api/v1/analytics/recommendations?subjectId=…` 共用每个学生、科目、版本的 60 秒缓存。规则掌握度为有效作答的正确率。推荐优先采用模型返回的合法候选题，其次按答错率与探索项排序，之后按已有预测值贪心排序，最后使用冷启动规则。

在服务进程配置 `AI_KT_ENABLED=true`、`AI_KT_BASE_URL` 和 `AI_KT_MODEL_VERSION` 后，后端向模型服务的 `POST /predict` 发送 JSON。连接与读取超时默认各为 800 毫秒，可由 `AI_KT_TIMEOUT_MS` 配置。

请求含 `subjectId`、`modelVersion`、`asOf`、`nodes`、`candidates` 和最近至多 250 条有效作答的 `sequence`。知识节点的 `prerequisiteIds` 指向同一科目中应先学的节点；不存在、自引用及会产生环的边会被过滤。目录可填写 `category`（`concept`、`calculation`、`memorization`）、`level` 和 `knowledgeVersion`。题目版本中的 `knowledgeVersion` 应指向发布时关联的知识点版本。老题的标准难度由已知文本映射，无法识别时留空。

模型服务返回以下结构，`recommendations` 为按优先级排列的候选题版本 ID 数组。

```json
{
  "modelVersion": "kt-gkt-v1",
  "items": [
    {
      "knowledgeId": "40000000-0000-4000-8000-000000000001",
      "mastery": 0.45,
      "confidence": 0.8,
      "stddev": 0.1,
      "weight": 0.65
    }
  ],
  "recommendations": ["51000000-0000-4000-8000-000000000001"]
}
```

模型版本须与请求一致。模型未返回的置信字段留空，模型不可用时返回本地结果。切换或回滚时将 `AI_KT_MODEL_VERSION` 指向推理服务实际提供的版本并重启后端，选填 `AI_KT_PREVIOUS_MODEL_VERSION` 可一并登记上一版。登记记录由 Flyway V14 创建的 `kt_model_versions` 表保存。推理与导出日志使用 `knowledgeTracing` 事件，可按 `latencyMs`、`source`、`modelVersion` 和 `fallbackReason` 聚合。
