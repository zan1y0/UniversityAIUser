### 为什么报告里会出现微软的域名？

因为报告里写着 **“No contexts were selected, so all contexts were included by default”**（没选上下文，默认包含所有站点）。

ZAP 启动的浏览器是 **Edge**，它会自动访问 SmartScreen 的遥测接口；这些流量走了 ZAP 代理，就被一起记进了历史，最后进了报告（各 1~2 个 endpoint，无警报）。

**这不是你的问题，是“没圈范围”导致的噪音。** 正确做法：建 Context + 把 `127.0.0.1:5173`、`127.0.0.1:8080` 加进 Scope。

## 三、6 条警报逐条判定

| # | 警报 | 风险/置信度 | 命中请求 | 判定 |
|---|---|---|---|---|
| 1 | Content Security Policy (CSP) Header Not Set | 中 / 高 | `GET /sitemap.xml` | 环境噪音（Vite dev 不设 CSP） |
| 2 | Missing Anti-clickjacking Header | 中 / 中 | `GET /sitemap.xml` | 环境噪音（同上） |
| 3 | X-Content-Type-Options Header Missing | 低 / 中 | `GET /src/main.ts` | 环境噪音（Vite dev 不设 nosniff） |
| 4 | Information Disclosure - Sensitive Information in URL | 信息 / 中 | `GET /?token=GFlyQ5-PWok9` | **误报**（Vite HMR 的 WebSocket token） |
| 5 | Information Disclosure - Suspicious Comments | 信息 / 低 | `GET /node_modules/.vite/deps/pinia.js` | 误报（Pinia 上游库里的 FIXME 注释） |

### 1 & 2 & 6：为什么都落在 `/sitemap.xml`

ZAP 的爬虫习惯性探测 `/sitemap.xml`。你的 Vite 是 SPA 模式，**任何不存在的路径都回落到 `index.html` 并返回 200**：

```http
GET /sitemap.xml → HTTP/1.1 200 OK
Vary: Origin
Content-Type: text/html
Cache-Control: no-cache
Content-Length: 588
```

于是 ZAP 认为“普通 HTML 页面缺少 CSP / 缺少 X-Frame-Options / 是个 SPA”，三条一起报。

- 这些响应头**本该由生产环境的 Nginx/网关加**，Vite dev server 从来不加；
- 你在本地看到它们，属于“开发环境本来就这样”，不是代码缺陷；
- 但请记住：**上线时必须有**（见第五节）。

### 3：`/src/main.ts` 缺 `nosniff`

```http
HTTP/1.1 200 OK
Content-Type: text/javascript
（没有 X-Content-Type-Options）
```

Vite dev 直接把 `.ts` 编译成 JS 返回，不设 `nosniff`。风险极低（现代浏览器已不靠嗅探决定 `text/javascript`），但生产静态服务器应该加上。

### 4：`?token=` 那条的真相 —— 这是本报告最值得学的一条

请求原文：

```http
GET http://127.0.0.1:5173/?token=GFlyQ5-PWok9 HTTP/1.1
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Protocol: vite-hmr
Origin: http://127.0.0.1:5173
→ HTTP/1.1 101 Switching Protocols
```

这是 **Vite 的 HMR（热更新）WebSocket 握手**，`Sec-WebSocket-Protocol: vite-hmr` 说明了一切。Vite 7 给 HMR 连接加了一个随机 token，防止别的网站偷偷连你的 dev server：

`frontend/node_modules/vite/dist/node/chunks/config.js` 里：

```js
function hasValidToken(config, url) {
  const token = url.searchParams.get("token");
  if (!token) return false;
  try {
    return crypto.timingSafeEqual(Buffer.from(token), Buffer.from(config.webSocketToken));
  } catch {}
  return false;
}
```

**结论：这个 token 是 Vite 自己的一次性握手凭证，不是你的业务 token，也不是漏洞。** ZAP 只是看到 URL 里有 `token=` 就报了。

顺带说一句：你自己应用的激活 token 放在 **hash** 里（`frontend/src/views/ActivationView.vue:6`：`new URLSearchParams(window.location.hash.slice(1)).get('token')`），hash 不会发给服务器、也不会进 Referer —— 这个设计是对的。哪天真把激活 token 放成 `?token=`，那才需要担心（会进浏览器历史、代理日志、Referer）。

### 5：Pinia 里的 FIXME

ZAP 在 `node_modules/.vite/deps/pinia.js` 里匹配到：

## 五、真正值得记下来的两点

### 1）生产环境的响应头（现在不用改，上线前必须加）

本地是 Vite dev + HTTP，所以以上全部缺失是“正常的”。上 Nginx 后统一加：

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

对应地，生产 `application.yml`：

```yaml
server:
  servlet:
    session:
      cookie:
        secure: true   # 必须 HTTPS
```

> 注意：`frame-ancestors 'none'` 和 `X-Frame-Options: DENY` 二选一即可，两个都写不冲突。

### 2）Vite dev server 不是你的“生产面貌”

这次扫出来的 88% 是 JS 模块、100% GET、SPA 回落 —— 全是**开发服务器**的特征。生产构建后：

- 页面由 Nginx 直接发静态文件；
- 没有 `/@vite/client`、没有 `node_modules/.vite/deps/*`；
- 没有 HMR WebSocket；
- 响应头由 Nginx 控制。

所以**别拿 dev 环境的扫描结果当项目安全结论**，这点在答辩/报告里要写清楚。

## 六、下次该怎么扫（把这次的教训变成流程）

1. 后端 8080 + 前端 5173 都启动，浏览器能正常登录；
2. ZAP 代理端口 **≠ 8080**（8090 或本机已配的 8081 都行）；
3. 新建 **Context**：Include `http://127.0.0.1:5173.*`、`http://127.0.0.1:8080.*`，**Scope 只留这两个**；
4. 快速开始 → **手动探索** → `http://127.0.0.1:5173/login`；
5. 在 ZAP 浏览器里**真的登录**，然后按路由清单逛 13 个页面，做翻页/搜索/看详情；
6. 确认 **历史里出现 `POST /api/v1/auth/login` 200 + `Set-Cookie: AUTH_TOKEN=...`**，以及 `127.0.0.1:8080` 的站点树；
7. 被动扫描结果先看一遍；主动扫描**只挑 GET 接口**，线程 2~3；
8. 出报告时在“Report Parameters”里确认只勾了这两个 Context。

做到第 6 步，你才会第一次看到真正有价值的警报（Cookie 属性、CORS、缓存、信息泄露……）。
