## 1. 这个后端是什么

这是“大学生考研 AI 导学系统”的 Java 后端。前端负责页面和用户操作，后端负责账号认证、数据保存、业务规则、文件管理、学习统计，以及调用外部模型完成讲解、答疑和部分评分任务。

业务分为 11 个模块：

| 模块 | 功能 | 主要业务类 |
| --- | --- | --- |
| M01 数字人 | 形象配置、互动、打卡、督学、提醒设置 | `AvatarService`、`DomainDispatcher` |
| M02 择校 | 院校专业筛选、推荐、指标、对比、风险评估 | `CatalogService`、`DomainDispatcher` |
| M03 公共课 | 英语、政治、数学知识树、讲解及学习反馈 | `CatalogService`、`DomainDispatcher` |
| M04 专业课 | 科目、教材章节、题目查询、讲解、历史频率 | `CatalogService`、`DomainDispatcher` |
| M05 答疑 | 图片识别、确认题目文字、多轮引导、取消生成 | `QaService`、`DomainDispatcher` |
| M06 练习 | 练习组题、作答、批改、错题、掌握率 | `PracticeService` |
| M07 计划 | 生成草稿、修改、确认、完成任务、调整计划 | `PlanService` |
| M08 模考 | 开考、保存答案、恢复、交卷、评分、排名、估分 | `ExamService` |
| M09 复试 | 模拟面试、追问、报告、自我介绍批改 | `InterviewService`、`DomainDispatcher` |
| M10 数据 | 学习事实、时长曲线、正确率、薄弱点、周报 | `AnalyticsService` |
| M11 政策 | 政策列表、版本差异、关注、日期、通知已读 | `NewsService`、`PolicyImportService` |

账号、备考档案、附件、异步任务和事件推送是多个模块共用的基础能力。

### 1.1 技术组成

| 技术 | 项目中的用途 |
| --- | --- |
| Java 17、Maven | 编写、依赖管理、构建和测试 |
| Spring Boot 3.3.5、Spring MVC | 自动装配、HTTP 路由、内嵌 Web 服务 |
| Spring JDBC / `JdbcTemplate` | 执行参数化 SQL，读取和修改数据 |
| H2、MySQL | local 使用 H2 文件库；mysql、dev、prod 使用 MySQL |
| Flyway | 启动时按版本执行建表迁移 |
| Jackson | 使用 `JsonNode`、`ObjectNode`、`ArrayNode` 表达业务数据 |
| JSON Schema Validator | 根据接口契约校验请求、响应和模型结果 |
| Spring Security Crypto / JOSE | BCrypt 密码哈希、JWT 签发和验证 |
| Java `HttpClient` | 调用兼容接口的外部文本、视觉、音频模型服务 |
| Spring Scheduling、Java 线程池 | 执行后台任务、考试截止检查、提醒和事件发送 |
| MockMvc、JUnit、Spring Boot Test | 在测试环境调用实际 HTTP 层和业务层 |

项目通过 OpenAPI JSON 描述业务字段，使用 Spring JDBC 保存聚合 JSON 快照。因此阅读时主要查“契约 + Service + Repository”，而不是寻找一整套 Entity、Mapper、DTO、VO 类。

## 2. 根包 `com.kaoyan.ai`：应用启动

### 2.1 `KaoyanAiApplication`

源码：[KaoyanAiApplication.java](../src/main/java/com/kaoyan/ai/KaoyanAiApplication.java)

这是后端的启动类。`main()` 调用 `SpringApplication.run()`，加载配置、创建 Spring 容器并启动 Web 服务。

- `@SpringBootApplication`：从 `com.kaoyan.ai` 向下扫描控制器、服务、仓库等组件，并启用自动配置。
- `@EnableScheduling`：让 `jobs` 包内的 `@Scheduled` 方法定期执行。

例如 `PracticeService` 的构造方法需要 `RecordRepository`，Spring 会注入已经创建的仓库对象。各业务类通常不需要自己 `new` 其他服务。

## 3. `controller` 包：HTTP 接口层

这个包回答“浏览器请求哪个 URL，会进入哪个 Java 方法”。多数模块控制器只做参数接收和委托：

```java
return api.execute("op045", paths, body, request);
```

这里 `op045` 是 OpenAPI 的 `operationId`，同时是源码的业务分发键。继续向下查 `ApiExecutor` 和 `PracticeService.execute()`，才能看到提交作答的实际逻辑。

控制器不让客户端传入任意 `userId` 来指定当前用户；当前用户从安全层提供的身份取得。以下逐个解释全部 13 个控制器。

### 3.1 `AuthController`：新账号认证入口

源码：[AuthController.java](../src/main/java/com/kaoyan/ai/controller/AuthController.java)

类级路径为 `/api/v1/auth`，提供四个方法：

| 方法 | HTTP 接口 | 实际作用 |
| --- | --- | --- |
| `register()` | `POST /register` | 调用 `AuthService.authenticate(..., true, ...)`，注册并登录，返回 201 |
| `login()` | `POST /login` | 调用 `authenticate(..., false, ...)`，验证密码并签发 JWT |
| `me()` | `GET /me` | 调用 `AuthService.current()` 返回当前用户的公开信息 |
| `logout()` | `POST /logout` | 撤销 JWT、清除认证 Cookie、销毁会话，返回 204 |

这些方法直接进入认证服务，不经过 `ApiExecutor`。私有 `result()` 统一构造成功响应，密码哈希不进入响应。

### 3.2 `SupportController`：跨模块基础接口

源码：[SupportController.java](../src/main/java/com/kaoyan/ai/controller/SupportController.java)

提供 `op001～op010`，并包含工作区新增的聊天附件入口。

| 方法 | 作用 | 下游 |
| --- | --- | --- |
| `op001()` | 获取或创建 CSRF 凭据 | `ApiExecutor → SessionService.csrf()` |
| `op002()` | 旧式会话账号密码登录 | `ApiExecutor → SessionService.login()` |
| `op003()` | 旧式会话退出 | `ApiExecutor → SessionService.logout()` |
| `op004()`、`op005()` | 读取、更新本人备考档案 | `ApiExecutor → ProfileService` |
| `op006()` | 上传指定用途的图片或音频 | 直接调用 `FileService.upload()` |
| `op007()` | 下载本人文件 | 直接调用 `FileService.download()` |
| `op008()` | 删除本人文件 | `ApiExecutor → DomainDispatcher → FileService` |
| `op009()` | 查询本人异步任务和结果 | `ApiExecutor → JobService.get()` |
| `op010()` | 建立 SSE 事件连接 | 直接调用 `EventService.subscribe()` |
| `uploadChatAttachment()` | `POST /api/v1/avatar/attachments`，上传普通聊天附件 | 直接调用 `FileService.uploadChatAttachment()` |

普通聊天附件保存为 `chatAttachment`，与 `qaImage` 等专用文件的检查路径不同。上传成功只说明文件已保存；这条上传路径本身没有实现附件内容解析或把附件内容交给模型。

旧 `/session/*` 登录与新 `/auth/*` 登录并存。新 JWT 登录应使用 `/auth/logout` 退出：旧退出方法只销毁会话，不负责撤销 JWT。

## 4. `security` 包：认证与请求安全

这个包先确定“你是谁、请求是否具备正确凭据”，然后业务层继续判断“这份资源是不是你的、当前状态能否操作”。

### 4.1 `SessionFilter`：所有请求前面的过滤器

源码：[SessionFilter.java](../src/main/java/com/kaoyan/ai/security/SessionFilter.java)

继承 `OncePerRequestFilter`，核心方法是 `doFilterInternal()`。

它为请求生成 `traceId`，设置禁止缓存、禁止 MIME 嗅探的响应头；读取允许来源配置，处理 CORS 和 OPTIONS。对 `/api/v1/` 下的受保护接口调用 `SessionService.user()`，对写请求检查 `X-CSRF-Token` 与会话值是否匹配，并检查带有 `Origin` 的请求来源。

CSRF 获取、两种登录及注册属于公开入口，但登录和注册仍要携带事先取得的 CSRF。过滤器捕获 `ApiException` 时直接输出统一错误 JSON；这条错误路径发生在 Controller 之前，不依赖 `ApiAdvice`。

### 4.2 `SessionService`：统一取身份，兼容旧会话

源码：[SessionService.java](../src/main/java/com/kaoyan/ai/security/SessionService.java)

| 方法 | 用途 |
| --- | --- |
| `csrf(request)` | 创建或读取 HttpSession 内的 CSRF 值 |
| `user(request)` | 优先取 JWT 并验证；没有 JWT 时读取旧会话的 `userId` |
| `login(request, name, password)` | 旧登录：BCrypt 校验密码、轮换会话 ID、写入 `userId`、清旧 CSRF |
| `logout(request)` | 销毁 HttpSession |

旧登录有基于会话的一分钟失败次数限制。携带无效 JWT 时会认证失败，不会自动退回旧 `userId` 身份。

### 4.3 `AuthService`：新注册和登录业务

源码：[AuthService.java](../src/main/java/com/kaoyan/ai/security/AuthService.java)

依赖 `UserAccountRepository`、`RecordRepository`、`JwtService` 和 `SessionService`。

`authenticate()` 用 `register` 参数区分注册和登录，在事务中完成以下处理：

1. 根据实际连接来源限流：每个窗口一分钟，最多 10 次；不信任客户端随意填写的转发 IP。
2. 校验账号、密码和注册昵称；账号去首尾空白并转为小写，密码限制 UTF-8 字节数。
3. 注册时用 BCrypt 强度 12 保存密码哈希，并创建初始 `profiles`；重复账号返回冲突。
4. 登录时验证密码；账号不存在也执行一次备用哈希比较，减少账号存在与否导致的处理差异。
5. 撤销请求中的旧有效令牌，轮换会话 ID，移除旧 `userId` 与 CSRF，签发新 JWT。

`current()` 通过统一身份查询账号，只返回 `id`、`loginName` 和 `displayName`。私有 `view()` 控制公开字段。限流窗口保存在进程内，重启会清空，多实例不共享。

### 4.4 `JwtService`：可撤销 JWT

源码：[JwtService.java](../src/main/java/com/kaoyan/ai/security/JwtService.java)

| 方法 | 用途 |
| --- | --- |
| `token()` | 优先读取 `Authorization: Bearer ...`，否则读取 `AUTH_TOKEN` Cookie |
| `verify()` | 验证 HS256 签名、签发者、接收方、时间、主体及数据库令牌记录 |
| `issue()` | 生成带 `jti` 的 JWT，写 `auth_tokens`，通过 HttpOnly Cookie 交给浏览器 |
| `revokeActive()` | 删除当前有效令牌的数据库记录 |
| `revoke()` | 撤销并通过过期 Cookie 清除浏览器令牌 |

默认有效期 1800 秒，可配置范围为 60～86400 秒。配置密钥使用 Base64，解码后至少 32 字节；mysql、dev、prod 未配置时启动失败，local 未配置时生成进程临时密钥。

认证因此同时使用三种凭据：

| 名称 | 作用 |
| --- | --- |
| `AUTH_TOKEN` | 新登录的 JWT 身份 Cookie，HttpOnly |
| `SESSION` | Servlet 会话 Cookie；承载 CSRF，旧登录还承载身份 |
| `X-CSRF-Token` | 写请求头，须与当前会话保存的值一致 |

新登录后须重新获取 CSRF。JWT 不是替代 CSRF 的东西；当前实现每次验证还查询 `auth_tokens`，并非完全无服务端状态。

## 5. `contract` 包：接口契约和统一执行

### 5.1 `ContractRegistry`：加载和执行接口约束

源码：[ContractRegistry.java](../src/main/java/com/kaoyan/ai/contract/ContractRegistry.java)

启动时加载类路径下 `contract/openapi.json`，按 `operationId` 建索引，编译并缓存 JSON Schema。展开 `$ref` 后也能将结构交给模型提示词。

| 方法 | 用途 |
| --- | --- |
| `operation()`、`status()` | 获取操作定义和约定的成功状态码 |
| `schema()` | 获取展开引用后的模型结构 |
| `request()` | 校验路径、请求头和 JSON 请求体 |
| `query()` | 解析查询参数为正确类型，拒绝未知、重复、缺失或类型错误的参数 |
| `validate()` | 用指定 Schema 验证数据 |
| `model()` | 验证业务对象、任务、事件或模型输出 |
| `response()` | 校验成功响应是否满足操作的约定 |
| `idempotent()` | 检查该操作是否声明 `Idempotency-Key` |

例如字段不符合契约时在进入业务之前失败；模型虽返回合法 JSON，但缺少规定字段时同样不算成功。新 `/auth/*` 和聊天附件入口没有通过这套统一执行器，不能假设所有路由都会自动执行同一套契约检查。

### 5.2 `ApiExecutor`：多数接口的统一执行入口

源码：[ApiExecutor.java](../src/main/java/com/kaoyan/ai/contract/ApiExecutor.java)

`execute()` 带 `@Transactional`，把请求校验、身份、写锁、去重、业务执行和成功响应串起来：

1. `ContractRegistry` 校验请求、解析查询参数。
2. 通过 `SessionService` 获取当前用户；取 CSRF 与旧登录操作有专门分支。
3. 写操作使用 `RecordRepository.lockOwner()` 锁定当前用户行。
4. 需要幂等时检查键与 `requestId`／`eventId` 的一致性，计算请求指纹。
5. 查询“用户 + 操作 + 幂等键”的旧结果；24 小时内同内容返回原响应，异内容返回冲突；过期记录删除后继续执行。
6. `op001～op003` 处理旧会话能力，其余交给 `DomainDispatcher`。
7. 构造并校验成功响应，保存幂等结果，与业务写入一起提交。

私有 `canonical()` 对 JSON 对象字段递归排序，使仅字段顺序不同的请求获得一致指纹。成功通常返回 `code`、`message`、`data`、`traceId`；204 直接返回空响应体。

## 6. `domain` 包：具体业务规则

这是项目最核心的业务包，共 13 个顶层类型。部分 Service 使用 `execute(String op, DomainContext c)` 处理自己负责的一组操作，它们没有实现共同的自定义 Service 接口。

### 6.1 `DomainContext`：一次操作携带的数据

源码：[DomainContext.java](../src/main/java/com/kaoyan/ai/domain/DomainContext.java)

这是 Java `record`，保存 `user`、`paths`、`query`、`body`。`path()` 取路径变量，`q()` 取查询字符串，`b()` 取请求体字符串，`integer()` 取请求体整数。

它把 HTTP 参数整理为业务易用的上下文，也让后台任务可以恢复原操作参数。它不是数据库实体，也不负责权限校验。

### 6.2 `DomainDispatcher`：模块路由与任务编排

源码：[DomainDispatcher.java](../src/main/java/com/kaoyan/ai/domain/DomainDispatcher.java)

依赖各业务 Service、`RecordRepository`、`JobService`、`FileService`、`ModelGateway`。这是“接口操作编号”和“业务实现”之间的总分发器。

| 方法 | 作用 |
| --- | --- |
| `execute()` | 判断同步或异步；同步调用对应业务服务 |
| `enqueue()` | 入队前检查资源、归属和版本，并准备消息、收卷或报告占位等资源 |
| `requiresModel()` | 指示任务是否需要在事务外完成耗时模型阶段 |
| `complete()` | 调用模型或执行规则，计算任务结果 |
| `persistModelResult()` | 在结果提交阶段更新识别记录、答疑消息、模考结果、复试轮次或报告 |

异步操作清单：

| 操作 | 处理内容 | 算法或依赖 |
| --- | --- | --- |
| `op014` | 数字人互动 | 文本模型；音频输入还要转写 |
| `op023` | 院校评估 | 数据可用性规则，缺校准样本时概率为 `null` |
| `op026`、`op033`、`op035` | 知识点、章节、题目讲解 | 文本模型 |
| `op028～op030` | 英政数学习反馈 | 文本模型 |
| `op036` | 历史考点分析 | 题库历史频率统计 |
| `op038` | 图片文字识别 | 视觉模型 |
| `op039` | 多轮答疑引导 | 文本模型 |
| `op050`、`op054` | 生成、调整计划 | 规则规划 |
| `op061` | 模考评分 | 客观题规则；已作答主观题需要模型 |
| `op064` | 快照估分 | 均值与标准差规则 |
| `op066`、`op067`、`op069` | 复试追问、报告、自我介绍批改 | 文本模型；音频作答先转写 |

“异步”表示后台执行，不等于一定使用 AI。`complete()` 也不意味着结果一律立即落库：模型结果要由提交阶段重新确认任务没有被取消，再调用 `persistModelResult()`。

### 6.3 `ProfileService`：备考档案

源码：[ProfileService.java](../src/main/java/com/kaoyan/ai/domain/ProfileService.java)

依赖 `RecordRepository`，管理 `profiles`。

- `get(user)`：按用户 ID 读取本人档案。
- `update(context)`：检查档案版本、目标专业存在性、基础分不高于满分，再合并请求字段并递增版本。

档案里的目标、日预算、基础成绩、当前计划会被择校和计划功能使用。新账号初始档案由 `AuthService` 创建。

### 6.4 `CatalogService`：公共资料查询

源码：[CatalogService.java](../src/main/java/com/kaoyan/ai/domain/CatalogService.java)

依赖 `RecordRepository`。它是公共院校、科目、知识树、书籍、题目和试卷的共享查询入口，主要读取 owner 为 `public` 的记录。

| 方法 | 作用 |
| --- | --- |
| `records()` | 列出某类公共资料 |
| `program()` | 查院校专业快照 |
| `subject()`、`knowledge()` | 从知识树查科目或知识点 |
| `questionVersion()` | 查含内部答案和解释的题目版本记录 |
| `displayQuestion()` | 仅取可展示的题目部分，避免直接发出完整内部题库记录 |
| `questions()` | 按科目、知识点、难度筛选可展示题目 |
| `facts()` | 组织某年份的分数线、招生数、报录比和缺失字段 |
| `publicTree()` | 移除内部分类字段，得到约定的知识树结构 |
| `execute()` | 处理择校、课程、题库、试卷列表和复试资料查询 |

院校推荐按地区、年份、难度、估计分数做规则匹配；无分数线时使用默认匹配分，同时提示不能当作录取概率。缺失的招生指标保持缺失，不编造数值。

### 6.5 `AvatarService`：数字人偏好、打卡和督学

源码：[AvatarService.java](../src/main/java/com/kaoyan/ai/domain/AvatarService.java)

依赖 `RecordRepository`。`execute()` 返回形象资源，读取和更新偏好／提醒，执行打卡和统计督学状态；`defaultSettings()` 在尚无设置时创建默认值。

关联 `avatar_preferences`、`reminder_preferences`、`checkins` 和 `plans`。打卡只能使用当前中国标准日期，同日重复返回原记录，连续天数根据前一天记录计算。督学状态从生效计划统计当天完成数和逾期任务。

`SHAPE` 是当前支持形象的固定 ID，形象使用静态 SVG；模型互动本身由 `DomainDispatcher` 完成。偏好中出现语音选项不代表后端已实现语音合成。

### 6.6 `PracticeService`：练习与错题

源码：[PracticeService.java](../src/main/java/com/kaoyan/ai/domain/PracticeService.java)

依赖 `RecordRepository`、`CatalogService` 和 `ModelGateway`。

`execute()` 覆盖组题、查询、提交作答、错题、历史、同类题、掌握率。创建练习时按条件选题并打乱顺序；每日最多取 5 题，其他类型最多取 20 题，实际数量不超过题库可用数量。

- `validateAnswer()`：检查作答类型、选项是否属于题目。
- `correct()`：数值题用 `BigDecimal` 比较，多选题按集合比较，其他类型按相应结构比较；供模考复用。
- 提交作答：校验题目属于该练习，客观题规则评分；文本主观题通过模型评分，分数不得超过满分。
- 错题：首次错误创建错题项；后续作答更新次数、时间和掌握标记。
- 掌握率：用知识点范围内的正确作答次数／作答次数估计，没有样本时返回 `null`。

主要数据为 `practice_sessions`、`attempts`、`wrong_items`。练习完成不会自动等同于计划任务完成或学习时长上报，它们有各自接口。

### 6.7 `PlanService`：规则学习计划

源码：[PlanService.java](../src/main/java/com/kaoyan/ai/domain/PlanService.java)

依赖 `RecordRepository`、`ProfileService`、`CatalogService`，主要操作 `plans`、`profiles`。

| 方法 | 作用 |
| --- | --- |
| `get()` | 获取本人计划 |
| `generate()` | 检查目标日期和档案版本，依据基础分与时间预算分配日任务，保存草稿 |
| `execute()` | 日／周／月视图、修改任务、确认、完成任务及查询进度 |
| `progress()` | 统计计划时长、完成时长、任务数及完成率 |
| `adjustment()` | 读取当前生效计划及档案，按新预算生成另一份调整草稿 |

权重使用 `1 + (1 - 基础分 / 满分)`，基础较弱科目分配更多时间；没有基础科目时从公共课程知识树选取。目标日期需晚于今天且小于三年，当前生成天数最多 730 天。

计划状态为 `draft → active → superseded`：只有草稿能直接修改任务，确认后写入档案的 `activePlanId`，原生效计划被替换。只有生效计划能完成任务，任务和整个计划各有版本。

当前调整实现按原目标、新预算和当前档案重新调用 `generate()`，生成新的日任务草稿；没有逐项复制原计划的已完成任务。阅读返回理由时，应以这段实际生成逻辑判断保留了哪些数据。

### 6.8 `QaService`：多轮答疑状态

源码：[QaService.java](../src/main/java/com/kaoyan/ai/domain/QaService.java)

依赖 `RecordRepository` 和 `CatalogService`，操作 `conversations`、`qa_messages`，并读取 `recognitions`、更新关联 `jobs`。

- `execute()`：创建科目会话、查询消息列表／单条消息、取消生成。
- `prepareMessage()`：禁止同会话重复排队，校验科目和 `contextVersion`、识别记录归属，递增上下文版本，保存用户消息和待生成的助手消息。
- `context()`：整理历史输入和引导内容，保留最后最多 24000 个字符供模型使用。

OCR 记录要求用户确认识别文字，然后才作为答疑输入。模型生成发生在 `DomainDispatcher`，目标是返回步骤、提示和方法。取消会同步改变消息与关联任务状态；提交阶段再次检查，防止模型晚到结果覆盖取消状态。

### 6.9 `ExamService`：模考生命周期与成绩

源码：[ExamService.java](../src/main/java/com/kaoyan/ai/domain/ExamService.java)

依赖 `RecordRepository`、`CatalogService`、`PracticeService`、`ModelGateway`。

| 方法 | 作用 |
| --- | --- |
| `session()` | 读取本人考试会话并补充当前 `serverTime` |
| `paper()` | 读取公共试卷版本 |
| `execute()` | 开考、恢复、保存答案、查询结果和匿名排名 |
| `ensureOpen()` | 检查仍在考试中，且服务端截止时间未到 |
| `close()` | 校验会话版本，标记已交卷，创建待评分结果 |
| `grade()` | 客观题按答案评分，主观题按参考及量尺调用模型，汇总成绩 |
| `saveResult()` | 更新结果；评分完整时保存 `score_snapshots` |
| `estimate()` | 对本人同量尺成绩快照计算均值和离散范围 |

开考时保存题目快照、服务端开始时间和截止时间；同一试卷版本存在未到期考试时阻止重复开考。保存答案分别检查题目答案版本并更新会话版本。恢复读取不会延长考试。

主观题服务失败时用 `PartialScoringException` 携带已算出的客观题成绩，总分与主观估计保持 `null`，不生成完整成绩快照、不参与完成成绩排名。完全由客观题组成的考试可无需模型完成。

排名基于同一试卷版本的完整评分，并按用户去重，显示匿名名称；估分只接收本人相同满分量尺的成绩快照。少量样本的均值与标准差范围不是统计置信区间，也不承诺录取。

### 6.10 `InterviewService`：复试会话与结束状态

源码：[InterviewService.java](../src/main/java/com/kaoyan/ai/domain/InterviewService.java)

依赖 `RecordRepository`、`CatalogService`。

`execute()` 创建复试会话并按专业、英语、压力模式提供起始问题，也负责读取报告。`ensureRunning()` 检查会话仍在进行且未超过约定时长；`finish()` 校验版本、标记结束并创建待生成报告。

主要数据为 `interviews`、`interview_turns`、`interview_reports`。起始问题来自当前代码规则，后续反馈和追问才调用模型。文字或音频回答由分发器编排，音频先转写，不能从会话创建成功推断音频模型已经配置。

### 6.11 `AnalyticsService`：学习事实与统计

源码：[AnalyticsService.java](../src/main/java/com/kaoyan/ai/domain/AnalyticsService.java)

依赖 `RecordRepository`、`CatalogService`。主要读取 `study_events`、`attempts`、题目资料；关联学习任务时检查其属于本人计划。

`execute()` 上报学习事件、组织总览曲线、统计知识点掌握率并生成规则周报。私有 `intervals()` 排序和合并重叠时间段；`minutes()` 计算区间并集；`attempts()` 按日期／科目筛选作答，`rate()` 计算正确率。

例如 09:00～10:00 和 09:30～10:30 两个事件，累计有效时长为 90 分钟。日统计边界使用 `Asia/Shanghai`，不是简单按 UTC 日期切分。事件必须为已发生的正时长，单次不超过 24 小时；普通区间查询最多覆盖 366 天。

同 `eventId` 不同内容会冲突，没有作答样本时正确率返回 `null`。专注度是用户自评的时长加权统计，不能理解成摄像头、眼动或其他自动注意力检测结果。

### 6.12 `NewsService`：政策查询、关注与通知

源码：[NewsService.java](../src/main/java/com/kaoyan/ai/domain/NewsService.java)

依赖 `RecordRepository`、`CatalogService`。主要使用 `notices`、`notice_revisions`、`news_follows`、`milestones`、`notifications`。

`execute()` 按年份、院校和地区查询政策；比较两个政策版本的标题、正文、发布时间和来源；读取／更新关注设置；查询关键日期、通知，并按版本标记已读。私有 `follows()` 在用户没有关注配置时建立默认配置。

它读取已入库政策，不负责自动联网采集。新数据来自本地种子或 `PolicyImportService`。

### 6.13 `PartialScoringException`：部分评分异常

源码：[PartialScoringException.java](../src/main/java/com/kaoyan/ai/domain/PartialScoringException.java)

继承 `ApiException`，在失败信息之外保存部分评分 JSON，`partial()` 返回该结果。`ExamService.grade()` 抛出它，`JobWorker` 识别后保存可用成绩，使“主观题依赖失败”不会丢掉已得到的客观题成绩。它是携带业务上下文的异常，不是独立评分器。

## 7. `persistence` 包：数据库访问

这个包把内存中的 JSON 业务对象保存到数据库，再按用户和资源 ID 取回。账号、幂等记录和事件使用专用仓库，其余多数聚合走共用的 `RecordRepository`。

### 7.1 `RecordRepository`：业务聚合快照仓库

源码：[RecordRepository.java](../src/main/java/com/kaoyan/ai/persistence/RecordRepository.java)

内部使用 `JdbcTemplate`，`TABLES` 白名单限制允许访问的 34 张聚合表。每个业务聚合保存到独立表，表中常用字段为：

| 字段 | 作用 |
| --- | --- |
| `id` | 数据库记录标识，部分是业务组合键 |
| `owner_id` | 所属用户；公共资料为 `public` |
| `version` | 数据库并发版本 |
| `payload` | 业务 JSON 快照，含任务、题目等内部结构 |
| `created_at`、`updated_at` | 创建和更新时间 |

| 方法 | 用途 |
| --- | --- |
| `create()` | 新建聚合记录 |
| `get()`、`find()` | 按表、ID、owner 查记录；不存在分别抛 404 或返回空 Optional |
| `publicGet()` | 固定 owner 为 `public` 查询公共资料 |
| `list()` | 列出指定 owner 的记录 |
| `update()` | 按 ID、owner、预期 version 更新；影响行数不为 1 则抛版本冲突 |
| `replace()` | 先查当前数据库版本，再调用版本更新 |
| `delete()` | 按 ID 和 owner 删除 |
| `lockOwner()` | `SELECT ... FOR UPDATE` 锁定账号行，协调同用户写入 |
| `fingerprint()` | 对 JSON 内容计算 SHA-256 |
| `jdbc()` | 为后台扫描等场景提供底层 JDBC |

表名经过白名单后才能拼接，具体值用 SQL 参数绑定。owner 条件负责隔离，version 条件负责防止旧页面覆盖新数据；用户行锁负责事务内同用户写操作串行化。

业务对象常自行设置下一版本后调用仓库，不能认为仓库会同步修正 JSON 的全部字段。部分接口先读取列表再用 Java 筛选和分页，当前未全部实现数据库层分页。

### 7.2 `UserAccountRepository`：账号专用仓库

源码：[UserAccountRepository.java](../src/main/java/com/kaoyan/ai/persistence/UserAccountRepository.java)

操作 `app_users`：`findByLoginName()` 用于登录，`findById()` 用于当前用户查询，`existsById()` 用于初始化判断，`create()` 插入账号。SQL 参数使用绑定方式。

返回内部 `Account` record，包含 ID、登录名、昵称、密码哈希。它的 `toString()` 隐去密码哈希；对外响应仍必须通过认证服务筛选字段，不能直接返回 Account。

### 7.3 `IdempotencyRepository`：请求去重结果

源码：[IdempotencyRepository.java](../src/main/java/com/kaoyan/ai/persistence/IdempotencyRepository.java)

操作 `idempotency_records`。`find()`、`save()`、`delete()` 按“用户 + operationId + 幂等键”读写请求指纹、HTTP 状态、原响应和创建时间。

它保存的是已经返回的响应，不是重新执行业务的指令。24 小时复用和内容冲突策略由 `ApiExecutor` 决定。返回值为内部 `Entry` record。

### 7.4 `EventOutboxRepository`：持久事件账本

源码：[EventOutboxRepository.java](../src/main/java/com/kaoyan/ai/persistence/EventOutboxRepository.java)

操作 `event_outbox`。`reserve()` 插入占位并获取数据库自增事件 ID；`complete()` 按 owner 填完整载荷；`latest()` 取用户最新游标；`after()` 读取该用户游标之后最多 100 条事件。

事件通过内部 `Event` record 返回，包含数字 ID、事件类型、JSON 内容。数据库生成 ID 适合断线续读，不是公开资源 UUID，也不是消息中间件队列。

### 7.5 `LocalDataInitializer`：本地样例初始化

源码：[LocalDataInitializer.java](../src/main/java/com/kaoyan/ai/persistence/LocalDataInitializer.java)

实现 Spring Boot `ApplicationRunner`，应用启动时调用 `run()`。仅 `app.seed-local=true` 时运行；检测主样例用户已存在则整体跳过。

初始化示例账号、档案、院校、知识树、科目、题目、参考书、试卷等数据，供本地联调。首次创建示例账号必须设置 `LOCAL_STUDENT_PASSWORD`，密码用 BCrypt 哈希保存；已有账号不因修改环境变量而改密码。

这些资料明确标记为样例，缺失招生指标保持空值。mysql、dev、prod 默认关闭种子初始化；新 MySQL 库不能假设有 `student` 账号或完整课程资料。

## 8. `jobs` 包：后台任务、调度与事件

### 8.1 `JobService`：入队和查询

源码：[JobService.java](../src/main/java/com/kaoyan/ai/jobs/JobService.java)

依赖 `RecordRepository`。`enqueue()` 创建 `jobs` 任务状态和同 ID 的 `job_commands` 参数快照，返回 `jobId`、`status`、`resultUrl`、`resourceId`；`get()` 只查本人的任务。

每用户排队与运行任务合计达到 20 个时拒绝继续入队。任务记录保存进度、结果、错误、版本和时间；命令快照保存操作编号、路径、查询参数和请求体，用于后台重建 `DomainContext`。

### 8.2 `JobWorker`：实际执行任务

源码：[JobWorker.java](../src/main/java/com/kaoyan/ai/jobs/JobWorker.java)

依赖仓库、分发器、契约、事件服务和事务管理器。`poll()` 每 500 毫秒找 queued 任务，固定线程池并发 2 个；进程内 `active` 集合避免当前进程重复调度同一任务。

私有 `run()` 分成以下阶段：

1. 事务内锁用户，确认 queued，改为 running。
2. 从 `job_commands` 恢复参数。需要模型的计算在数据库提交事务之外执行。
3. 再进事务，锁用户并重新检查取消状态；落业务结果，校验 Job 结构，更新任务并发布事件。
4. 出错则记录错误；503、504 对应可重试失败，其他按实际错误记为失败；同步更新消息、报告或考试结果。

完整评分会额外发布 `exam.scored` 并建立通知。部分评分异常会保存其有效成绩。`shutdown()` 在应用销毁时停止线程池。

任务状态主要为 `queued → running → completed / failed / failed_retryable`，答疑还支持 `cancelled`。可重试表示允许重新提交，并不代表存在自动重试循环。

### 8.3 `JobRecovery`：重启后的中断处理

源码：[JobRecovery.java](../src/main/java/com/kaoyan/ai/jobs/JobRecovery.java)

监听 `ApplicationReadyEvent`，事务方法 `recover()` 扫描上次遗留的 running 任务，标记 `failed_retryable`，更新关联答疑消息、模考结果或复试报告，并发布失败事件。

它防止页面永久停在运行中，不会自动恢复上次模型 HTTP 连接，也不会无条件重放模型请求。queued 任务仍由 Worker 后续读取。

### 8.4 `ExamDeadlineService`：服务端自动收卷

源码：[ExamDeadlineService.java](../src/main/java/com/kaoyan/ai/jobs/ExamDeadlineService.java)

`closeExpired()` 每 5 秒检查 `exam_sessions`。发现已到期且仍在进行的考试后，在事务内锁定用户、重读会话状态，再通过 `DomainDispatcher.execute("op061", ...)` 收卷并安排评分。

浏览器关闭不会延长考试。截止后保存答案由 `ExamService` 拒绝；状态收卷由定时扫描完成，扫描周期意味着不保证在截止的同一毫秒完成状态更新。

### 8.5 `ReminderService`：站内学习提醒

源码：[ReminderService.java](../src/main/java/com/kaoyan/ai/jobs/ReminderService.java)

`remind()` 每 60 秒扫描生效计划，读取 `reminder_preferences`；启用且到达中国标准提醒时间后，为到期或逾期未完成任务发布 `task.reminder`，写入通知。

同一任务同一中国标准日期查重，避免每分钟重复提醒。依赖 `RecordRepository`、`EventService`、事务管理器。这里实现的是站内通知及事件，没有短信或邮件发送器。

### 8.6 `PolicyImportService`：本机政策文件导入

源码：[PolicyImportService.java](../src/main/java/com/kaoyan/ai/jobs/PolicyImportService.java)

`refresh()` 每 60 秒运行；没有配置 `app.policy-file` 时直接返回。配置后读取不超过 5,000,000 字节的本机 JSON 文件，校验 `notices` 和 `milestones`，要求真实政策有来源，更新版本连续递增。

写入 `notices`、`notice_revisions`、`milestones`，根据年份、院校、地区等关注范围通知用户，发布 `policy.updated` 并保存通知。依赖仓库、契约和事件服务。这是读取已核实文件，不是自动爬取互联网资讯。

### 8.7 `EventService`：事件发布、通知与 SSE

源码：[EventService.java](../src/main/java/com/kaoyan/ai/jobs/EventService.java)

| 方法 | 作用 |
| --- | --- |
| `publish()` | 获取事件 ID，校验 `EventPayload`，写入持久事件账本 |
| `notify()` | 保存站内通知到 `notifications` |
| `subscribe()` | 创建 SSE 连接；校验 `Last-Event-ID`，单用户最多 5 个连接 |
| `deliver()` | 每秒读取连接游标后的事件，逐个发送，约每 15 秒发送心跳 |

`Client` 内部类保存用户、Emitter、会话、会话 ID、游标和心跳时间。首次连接没带 `Last-Event-ID` 时从用户最新事件之后开始，带合法游标时可续读历史事件。

**当前源码的认证兼容边界：** `subscribe()` 通过统一身份认证，但 `deliver()` 继续检查旧 `HttpSession.userId`；新 JWT 登录恰好会移除它。因此新登录建立连接后可能在后续发送周期被关闭，不能把“连接成功”当作 JWT SSE 已经完整适配。任务的 HTTP 查询是独立路径，仍可用于轮询。

## 9. `ai` 包：外部模型适配

### 9.1 `ModelGateway`

源码：[ModelGateway.java](../src/main/java/com/kaoyan/ai/ai/ModelGateway.java)

这是所有模型 HTTP 调用的公共适配层，负责配置检查、请求构造、响应解析和结构校验，依赖 `ContractRegistry`。

| 方法 | 作用 |
| --- | --- |
| `ready()` | 检查基础地址、API key、文本模型名 |
| `version()` | 返回配置的文本模型标识 |
| `structured()` | 调用 `chat/completions`，支持文本或带 Base64 图片的请求 |
| `withSchema()` | 把目标 JSON Schema 和约束加入文本提示，再调用结构化接口 |
| `recognize()` | 把识别 Schema 与图片一起提交视觉模型 |
| `transcribe()` | 构造 multipart 请求，调用 `audio/transcriptions` 获取文本 |
| `sendJson()`、`send()` | 私有 HTTP 发送与错误转换 |

文本请求非流式，`stream=false`，要求服务返回 JSON，再进行契约校验。HTTP 连接超时为 10 秒，请求超时默认 45 秒；模型配置缺失、调用失败或结构不合法时返回明确依赖错误，超时为 `PROVIDER_TIMEOUT`。

图片还要求配置视觉模型，转写还要求音频模型；当前 `ready()` 也要求基础文本模型配置齐全。数字人回复的音频文件 ID 固定为空，后端没有在此实现语音合成服务。SSE 发送的是任务和业务事件，不是模型逐 token 输出。

## 10. `storage` 和 `common`：文件与公共能力

### 10.1 `storage.FileService`：私有附件存取

源码：[FileService.java](../src/main/java/com/kaoyan/ai/storage/FileService.java)

依赖 `RecordRepository`、`SessionService`、`ContractRegistry`、`AudioInspector`，读取 `app.files-directory`。构造时创建私有文件目录；内容按后端生成 UUID 命名，元信息写入 `files`。

| 方法 | 用途 |
| --- | --- |
| `upload()` | 上传 `qaImage`、`avatarAudio`、`interviewAudio`；检查大小、文件头与声明 MIME、用途、音频时长 |
| `uploadChatAttachment()` | 保存大小合规的普通聊天附件，元信息为 `application/octet-stream`，返回附件 ID |
| `metadata()` | 按 ID、用户、可选用途读取元信息 |
| `bytes()` | 先检查元信息归属／用途，再读二进制内容，供识别与转写使用 |
| `download()` | 校验下载参数，鉴权并按元信息 MIME 返回下载内容 |
| `delete()` | 确认本人文件，检查没有排队／运行任务引用后删除 |
| `location()`、`detect()` | 私有方法：限制文件定位范围、识别专用上传的文件头 |

两种上传均限制非空且不超过 10 MiB。专用上传支持 JPEG、PNG、WebP、WAV、MP3、OGG、WebM 的对应路径；普通聊天附件没有这套文件头和用途格式检查，也没有自动解析文件正文。

磁盘文件写入和数据库事务不是同一种资源事务，不能把 `@Transactional` 理解成两者会天然原子提交；普通聊天附件路径对写入／插入失败有清理处理。文件存放在私有目录，不能通过静态资源 URL 任意读取。

### 10.2 `storage.AudioInspector`：检查音频实际时长

源码：[AudioInspector.java](../src/main/java/com/kaoyan/ai/storage/AudioInspector.java)

核心方法 `duration(bytes, mime)`。WAV 用 JDK 音频 API 读取帧数和帧率；其他格式写临时文件，调用配置的 `ffprobe` 获取时长。

要求实际时长大于 0 且不超过 600 秒。外部检查最多等待 10 秒，结束清理进程和临时文件；未配置工具时明确返回依赖不可用。它负责校验，不负责转写，转写由 `ModelGateway` 完成。

### 10.3 `common.Jsons`：JSON 和基础规则工具

源码：[Jsons.java](../src/main/java/com/kaoyan/ai/common/Jsons.java)

这是不能实例化的静态工具类，提供统一 `ObjectMapper` 和业务时区 `ZONE=Asia/Shanghai`。

| 方法 | 作用 |
| --- | --- |
| `obj()`、`arr()` | 构造 JSON 对象和数组 |
| `parse()`、`text()` | 解析 JSON、取文本字段 |
| `id()` | 生成 UUID |
| `now()` | 当前 UTC Instant 字符串 |
| `today()` | 当前中国标准日期 |
| `require()` | 业务条件不满足时抛 422 `VALIDATION_FAILED` |
| `version()` | 版本不同抛 409 `VERSION_CONFLICT` |
| `page()` | 对已加载 Java 列表分页，默认第 1 页、每页 20 条 |

因此“时间点用 UTC”与“业务日历用中国标准日期”在代码里同时存在；`page()` 也不等于执行 SQL LIMIT 分页。

### 10.4 `common.ApiException`：业务错误载体

源码：[ApiException.java](../src/main/java/com/kaoyan/ai/common/ApiException.java)

继承 `RuntimeException`，携带 HTTP `status`、业务 `code` 和消息。`missing()` 创建 404 资源不存在／不属于本人错误；`state()` 创建 409 非法状态错误。

Service 通过抛出它结束当前操作，由边界组件转换成 HTTP 响应。这样可避免每个方法手写 ResponseEntity，也能让事务按异常传播处理回滚。

### 10.5 `common.ApiAdvice`：统一 HTTP 异常响应

源码：[ApiAdvice.java](../src/main/java/com/kaoyan/ai/common/ApiAdvice.java)

使用 `@RestControllerAdvice` 处理控制器链路异常：

- `business()`：保留 `ApiException` 的状态和业务码；429 带 `Retry-After: 60`。
- `invalid()`：将 JSON 无法读取或上传超限转换为 400 请求错误。
- `unexpected()`：记录带 `traceId` 的服务器日志，向客户端返回通用 500 错误。

错误响应包含 `code`、`message`、`data=null`、`traceId`、`details`。过滤器错误由 `SessionFilter` 自己转换，后台任务错误主要进入 Job 的 error 字段，三者的处理位置不同。

## 13. 把这些类连起来：五条典型调用流程

### 13.1 注册与登录

```text
先 GET /api/v1/session/csrf，取得 SESSION 与 CSRF
  → POST /api/v1/auth/register 或 /login，携带 SESSION 和 X-CSRF-Token
  → SessionFilter 检查 CSRF、来源
  → AuthController
  → AuthService 校验参数、账号、密码
  → UserAccountRepository；注册另创建 profiles
  → JwtService 写 auth_tokens，设置 AUTH_TOKEN
  → 轮换会话，清旧 CSRF
  → 再 GET /api/v1/session/csrf，取得新 CSRF
```

### 13.2 提交练习答案

```text
请求带身份 Cookie、CSRF、幂等键和作答
  → SessionFilter
  → Module06Controller.op045()
  → ApiExecutor：契约、用户锁、幂等
  → DomainDispatcher.execute()
  → PracticeService.execute()
  → CatalogService 核对题目版本与参考答案
  → 规则或模型评分，更新 attempts / wrong_items
  → ApiExecutor 校验响应并保存幂等记录
  → 同一事务提交
```

例如按钮重复点击且请求键、内容相同，会复用第一次结果，而不是生成两条作答。

### 13.3 图片答疑

```text
上传图片 → FileService 校验并保存文件
  → op038 创建识别任务 → JobService 保存任务、命令
  → JobWorker → DomainDispatcher.complete() → ModelGateway.recognize()
  → 提交事务保存 recognitions 和 Job 结果
  → 用户确认题目文字
  → op039 → QaService.prepareMessage()，保存两条消息
  → 创建答疑任务 → 模型读取会话上下文并生成引导
  → 再检查取消状态，保存助手消息
```

前端通过 `/api/v1/jobs/{id}` 查询结果；SSE 的 JWT 兼容情况见 `EventService` 一节。

### 13.4 模考自动交卷

```text
ExamService 开考并保存 deadlineAt
  → 前端逐题保存答案，每题带答案版本
  → 截止前可主动提交；截止后 ExamDeadlineService 扫描
  → DomainDispatcher 的 op061
  → ExamService.close() 标记提交并建结果占位
  → JobService 创建评分任务
  → JobWorker 调用 ExamService.grade()
  → 完整结果：保存结果、成绩快照、事件、通知
  → 部分失败：保留有效成绩，记录失败且总分为空
```

### 13.5 规则计划生成与确认

```text
op050 携带档案版本、目标日期、日预算、基础分
  → DomainDispatcher 校验并入队
  → JobWorker → PlanService.generate() → 保存 draft
  → 查询草稿，可修改任务
  → op053 → PlanService 检查草稿和档案版本
  → 原 active 计划变 superseded，新草稿变 active
  → profiles.activePlanId 更新
  → 后续完成任务、查询进度，提醒服务检查到期任务
```

## 15. 测试包：每个测试类做什么

所有测试类位于 `src/test/java/com/kaoyan/ai/`。测试帮助理解实际边界，但文档列出用例不等于本次执行过用例。

### 15.1 `KaoyanAiApplicationTests`

源码：[KaoyanAiApplicationTests.java](../src/test/java/com/kaoyan/ai/KaoyanAiApplicationTests.java)

`contextLoads()` 使用测试 H2 配置加载 Spring 上下文，验证主要组件可装配。它覆盖启动基础能力，不是所有模块业务验收。

### 15.3 `BackendContractTests`

源码：[BackendContractTests.java](../src/test/java/com/kaoyan/ai/BackendContractTests.java)

用 MockMvc 调用实际控制器和服务，覆盖多模块成功与失败流程：所有权、严格字段和版本、幂等及并发、目录、模型未配置、打卡、练习、计划、模考、答疑取消、学习区间去重、政策、事件、服务端截止及文件检查。内部 `Client` 简化会话、CSRF 和请求组织。

### 15.4 `BackendModelFlowTests`

通过测试专用模型替身验证主观评分成功后产生快照、评分失败保留客观分但无总分、模型调用期间取消后不提交晚到结果。内部配置和替身见第 11 节。

## 16. 阅读与修改代码时怎么定位

| 想理解或调整什么 | 推荐查找顺序 |
| --- | --- |
| 某接口接收哪些字段 | Controller 路由 → 运行时 OpenAPI 对应 operation 和 Schema |
| 某模块的规则 | Controller 的 op 编号 → `DomainDispatcher` → 对应 Service |
| 登录或 CSRF 失败 | `SessionFilter` → `SessionService` → `AuthService`／`JwtService` |
| 写入重复或版本冲突 | `ApiExecutor` → `IdempotencyRepository` → `RecordRepository.update()` |
| AI 任务没有完成 | `JobService` → `JobWorker` → `DomainDispatcher.complete()` → `ModelGateway` |
| 成绩部分失败 | `ExamService.grade()` → `PartialScoringException` → `JobWorker` 失败分支 |
| 查询不到本人记录 | 当前身份 → Service 使用的 ID → Repository 的 owner 条件 |
| 附件上传下载问题 | `SupportController` → `FileService` → `AudioInspector`／磁盘路径 |
| 定时提醒或政策更新 | `ReminderService`／`PolicyImportService` → `EventService` |
| 数据为什么是这样保存的 | Service 构造的 JSON → `RecordRepository` → Flyway SQL |
