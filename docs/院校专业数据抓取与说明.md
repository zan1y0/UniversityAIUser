## 2. 一条记录的口径

**记录粒度 = 招生单位 × 专业 × 院系所 × 学习方式 × 考试方式。**
这个粒度是研招网公示计划的最小口径：同一院系同一专业下不同研究方向共用同一个计划数，因此**不能按研究方向行相加**。归一化时按上述五元组去重，研究方向合并成 `研究方向` 一列。

计划数的字段含义（已按官方语义校正）：

- `招生计划（合计）` = 研招网 `nzsrs`，该专业在该院系的计划总数（含推免）
- `推免人数` = 研招网 `ssjstmrs`
- `招生计划（统考/不含推免）` = 合计 − 推免，即统考实际可竞争名额
- `计划口径` 保留研招网原文，例如「专业：65(含推免55)」

## 4. 已知限制（必须知道）

1. **研招网未登录只返回前 10 行。** 分页请求会返回 `{"msg":"请登录"}`，因此：
   - 一级学科下专业超过 10 个的，本批次只收录了该学科前 10 个专业（`data/2026/majors_truncated.json` 记录 23 个被截断学科的实际专业数，如法学 105、临床医学 119）；
   - 一个专业的院校清单超过 10 所的，只取前 10 所，字段 `专业是否完整` 标为「否」。
   - 这两处是本批次与「全部院校全部专业」的主要差距，扩量方法与断点见第 5 节。
2. **抓取限速。** 站点在约 1–2 请求/秒以上会返回 `访问太频繁`，所以全量抓取只能按优先级分批推进。当前批次按「专业热度 × 院校层级」排序，优先覆盖电子信息、计算机、金融、法律、临床医学等报考量大的专业和 985/自划线院校（400 个「专业×院校」组合，8 个组合因重试耗尽未取到）。
3. **复试线的层级不同。** 研招网合辑给的是「校线/学科门类线」，不是「某专业复试线」。院系线、专业线散落在各校复试细则里，格式不统一，需要逐校解析，属于后续增量工作。
4. **2023–2025 的招生计划**无法从研招网回溯（只保留当年目录）。这部分要回到各校研究生院官网的历年招生简章/录取名单，脚本框架已具备，但需要逐校适配。
5. **跨年对比**：本表只有 2026 年招生计划 + 2023 年校线。要做「同专业 2023→2026 计划/分数线趋势」，需要按第 4 条补 2023–2025 的院校官网数据。

## 5. 复现与扩展

```bash
# 0) 依赖：仅 Python 标准库 + pandas/openpyxl（出表用）
# 1) 专业清单（一级学科 -> 前 10 个专业 + sign token）
python scripts/scrape/list_majors.py 2026
# 2) 专业 -> 院校（每个专业一次查询）
python scripts/scrape/chsi_catalog.py --tag 2026 --stage pairs --workers 2
# 3) 专业 x 院校 -> 招生计划/科目（可先用 prioritize_pairs.py 排序再限量）
python scripts/scrape/prioritize_pairs.py 400
python scripts/scrape/chsi_catalog.py --tag 2026 --stage rows --workers 3 --pairs-file pairs_priority.jsonl
# 4) 归一化 + 校验 + 出表
python scripts/scrape/build_programs.py --tag 2026
python scripts/scrape/validate_data.py
python scripts/scrape/export_excel.py
# 5) 生成 Flyway 迁移（导入项目 programs 表）
python scripts/scrape/export_sql.py
```

扩量的做法：去掉 `prioritize_pairs.py` 的限量、把 `--pairs-file` 换回 `pairs.jsonl`，并把 `--walk-pairs` 打开即可继续向后翻页；脚本按 `*_done.txt` 断点续跑，重复执行不会产生重复记录。
